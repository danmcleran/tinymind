# benchmarks

Repo-wide rules are in the root `AGENTS.md`.

On-target benchmarks (comparisons against other frameworks, and tinymind against itself), kept outside `examples/` because they target Arm only (the top-level build and `check-clang-examples` compile every `examples/` Makefile with the host compiler); not built in CI. `framework_comparison_f411/`: tinymind vs TFLM (CMSIS-NN/reference) vs emlearn on a NUCLEO-F411RE, int8 outputs bit-exact with TFLM; `make deps` fetches the venv + TFLM, `make LEVEL=O3 run` flashes and captures. `make host-bench` times the same models on the build host, scalar vs each x86 SIMD backend the CPU supports. `SUITE=mlperf` (F411 only) runs the MLPerf Tiny reference KWS and ResNet-8 int8 models against TFLM instead; `make mlperf-models` fetches them (Apache-2.0, never committed: `gen/mlperf/` is gitignored), and results must not be called MLPerf results (no runner, unverified). `TOOLCHAIN=clang` builds the tinymind images with Clang through `clang-arm-cxx` (which adds `-munaligned-access` and `-fshort-enums`) into `<B>-clang` and `results/raw_*_clang.txt`. `IMG=x run1` flashes whatever ELF is already in `$(B)` and never rebuilds it: for an A/B comparison, build each variant into its own `B=` directory and confirm the disassembly differs before trusting identical cycle counts. Write-up: `docs/benchmarks.md`.

`fft_onboard/`: cycles per forward transform for `QFFT1D` (real input, zeroed imaginary buffer) vs `QRFFT1D` on the F411 and the L031 (`BOARD=l031`), at `LEVEL=O2|O3`, twiddle tables in flash or `TW=ram`; `IMG=fft1d` times `FFT1D<Q8.8>` instead, and `EXTRA=` adds compiler flags. GCC's register allocation for the int16 butterfly loop is fragile (#284: unrelated code moved a build from 1 to 16 stack accesses per butterfly), so after any change to `qfft1d.hpp` re-run every configuration, not one. It reuses `framework_comparison_f411/board/` and that directory's `local.mk` for the probe serials. A host program (`gen_tw.cpp`) writes the twiddle tables and the output hashes the board must reproduce; `make run` fails on a mismatch, and otherwise writes `results/raw_<board>_<level>[_twram].txt` (`raw_fft1d_<board>_<level>.txt` for `IMG=fft1d`). The tables it feeds are in `benchmarks/fft_onboard/README.md` and `docs/architectures/fft.md`.

## Benchmark harness (`cpp/include/bench/`)

- **`platform.hpp`** — `bench::readCycleCounter()` (DWT CYCCNT on Cortex-M, `std::chrono` host fallback) and `bench::paintStack` / `bench::stackHighWater` for MCU stack watermarking. Enable the MCU path with `-DTINYMIND_BENCH_CORTEX_M`.
- **`report.hpp`** — `bench::LayerStat` CSV row type, `bench::writeHeader` / `bench::writeRow` for any sink that supports `operator<<`, and a `bench::ScopedTimer` for per-layer measurements. See `examples/kws_cortex_m/` for an end-to-end use.

Per-layer numbers are only trustworthy when each layer is isolated with `noinline`; otherwise the compiler merges layers and the split is meaningless.
